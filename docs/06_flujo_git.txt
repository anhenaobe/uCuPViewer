POLÍTICA GIT PARA 6 PERSONAS - PROPUESTA

1. Este es un proyecto SEPARADO de Linux-Servers (mensajería TCP) y VibrationDAQ (DAQ de vibraciones). Nombre sugerido para repositorio remoto: uCuPViewer-Linux2 (pendiente de creación en GitHub).
2. Branch main: estado integrado que pase pruebas mínimas. Nunca subir directamente a main desde desarrollo cotidiano.
3. Ramas por tarea, no una eterna por persona: firmware/adc-dma, firmware/spi-commands, hardware/pinout, test/verification, frontend/dashboard, backend/spi-reader, infra/nginx. Nombres flexibles y según issue.
4. Crear Issue con: contexto, responsable, definición de terminado, dependencias, pruebas y rutas previstas.
5. Git: actualizar main antes de abrir nueva rama; commit pequeño y descriptivo; push de rama; PR hacia main. No mergear PR propio hasta la revisión prevista y las pruebas de integración relevantes.
6. Toda modificación a docs/03_contratos_interfaces_v0_1.txt requiere revisión conjunta de afectados. Cambiar documentación y tests en el mismo PR.
7. No modificar los archivos de reference/profesor/ (solo copiar/portar con atribución si se decide reutilizar). No versionar objetos .o, .d, target/, secretos, credenciales, capturas pesadas sin propósito.
8. Para evidencias, cada prueba queda asociada a commit SHA, placa y versión de firmware; los resultados de Checho no se reinterpretan sin volver a ejecutar el ensayo.
9. El repositorio podrá ser público o privado según decisión del equipo/docente; si hay material protegido del profesor, consultar permiso antes de publicarlo. Por defecto se recomienda PRIVADO hasta aclararlo.

COMANDOS INICIALES (después de crear repo remoto vacío con URL confirmada):
 git init -b main
 git add .
 git commit -m "docs: base del proyecto y referencias del profesor"
 git remote add origin URL_CONFIRMADA
 git push -u origin main

Si se crea repo remoto con README inicial, clonar primero y copiar la estructura para evitar divergencias de historias.
