DECISIÓN TÉCNICA INICIAL - STM32L432KC Y PLATFORMIO | 2026-10-29
Estado: plataforma seleccionada; rendimiento pendiente de ensayos físicos.

1. DECISIÓN Y COMPARACIÓN HISTÓRICA
Se selecciona STM32L432KC como única plataforma principal. Valeria realizó una evaluación inicial y considera más apropiado STM32; no se presenta esa evaluación como prueba física ni como medición de tasas.
STM32L432KC ofrece ADC de 12 bits, temporizadores, DMA y SPI que permiten plantear adquisición secuencial de dos canales disparada por hardware y ventanas estables. La combinación simplifica el control temporal y la integración con Raspberry Pi. Capacidad nominal no equivale a desempeño demostrado: medir cadencia, desfase CH1/CH2 e integridad sigue siendo obligatorio.
ESP32-S3 fue comparado por su capacidad de procesamiento, adquisición multicanal y SPI periférico. Sus funciones de conectividad no son necesarias porque HTTP reside en Raspberry Pi; su ruta de adquisición y preparación de transferencias exigiría validación propia. Se conserva este contexto histórico sin declarar inferioridad experimental. ESP32-S3 sale del desarrollo, asignaciones y ensayos obligatorios; no se mantendrá una segunda plataforma.

2. ENTORNO Y FRAMEWORK
Entorno: Visual Studio Code + PlatformIO. MCU: STM32L432KC. Framework inicial: STM32Cube HAL; CMSIS como soporte de bajo nivel; STM32 LL cuando convenga para periféricos críticos, documentando motivo e interacción con HAL. Sin RTOS en la implementación inicial.
Arquitectura propuesta: temporizador de hardware dispara secuencia ADC de dos canales; DMA guarda muestras; una máquina de estados bare-metal gestiona ventanas, comandos SPI y errores. Estas responsabilidades no requieren inicialmente un scheduler de RTOS. Interrupciones y DMA deberán coordinar propiedad de buffers y preparación TX; captura terminada no equivale a transferencia preparada.
Zephyr aporta servicios de kernel, sincronización, drivers y portabilidad valiosos para sistemas de mayor complejidad. Se pospone porque el alcance inicial no necesita múltiples tareas planificadas y añadiría configuración y capas que el equipo tendría que validar. No es una limitación de capacidad de Zephyr ni una comparación de rendimiento medida.
Esta tarea no crea platformio.ini, código HAL/CMSIS/LL ni firmware. Antes de la futura configuración, Andrew y Valeria confirman placa física, pines, reloj y método de programación; Andrew registra versiones de plataforma/framework y procedimiento reproducible. No se presupone una placa Nucleo solo por el nombre del MCU.

4. ESTIMACIONES, NO RESULTADOS
Ventana mínima: 64 pares x 2 canales x 16 bits = 256 B. A 1 MHz el payload ideal requiere 2,048 ms sin overhead. Un flujo continuo de 40.000 Sa/s/canal requiere 1,28 Mbit/s de payload, superior a ese SCLK inicial; captura por ventanas no obliga a streaming continuo.
64/fs es el presupuesto temporal de 64 periodos (0,640 / 0,064 / 0,0064 / 0,0016 s para los cuatro presets); la separación entre la primera y última muestra de un canal es 63/fs, y el tiempo completo depende del disparo y conversiones. Medir y declarar el criterio usado.
