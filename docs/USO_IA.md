## Criterios de documentación

1. Registrar las interacciones efectivamente utilizadas; no atribuir resultados no comprobados a un integrante.
2. Distinguir código original del equipo, material del docente y contenido asistido por IA.
3. Adjuntar enlaces o transcripciones cuando lo solicite la evaluación.
4. No presentar un código generado como funcional sin compilación, ensayo o revisión.
5. En cambios de arquitectura (por ejemplo, Raspberry Pi a Milk-V Duo S), registrar la revisión de documentos y código heredados.

**Antecedente:** el repositorio contiene `docs/07_aportes_ia.txt`, que puede conservarse como plantilla histórica. Este Markdown puede convertirse en el registro vigente, evitando mantener dos listas contradictorias.
